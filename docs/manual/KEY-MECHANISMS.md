# 关键机制
<div class="title-en">Key Mechanisms</div>

## 标准包边界

每个 `skills/<name>/` 都是一个独立 Agent Skills 包：

- `name` 与 `description` 支持发现和相关性判断。
- `SKILL.md` 是激活后的主指令。
- `references/`、`scripts/`、`assets/` 与其他 supporting files 按需加载。

仓库级文档、评测数据和根 `AGENTS.md` 不属于分发包。

## 渐进加载

主文件保留高显著性的目标、硬约束、工作流、输出契约与停止条件。长目录、变体检查、完整示例和仅少数场景使用的模板可以下沉到一层 supporting file，并由主文件明确说明何时读取。

把必读内容搬到 supporting file 并不会节省 token；只有真正按场景选择的材料才会减少常见路径成本。

## 组合而非大一统

技能按任务阶段组合：澄清、范围、设计、计划、执行、评审和验证各自承担清晰职责。任务不需要某个阶段时，不应为了流程完整而强制激活。

## 协议与生命周期

部分技能通过 `[output: ...]`、`[validate: ...]` 等紧凑块表达结果和交接。它们是内容契约，不依赖特定客户端。Skill 完成、被下游接管或任务改变时应及时停用。

## 运行时差异

开放标准不统一发现目录、调用语法、权限、子代理、上下文压缩或插件分发。本仓库不会在共享 `SKILL.md` 中假定这些行为。
