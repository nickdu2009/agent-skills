# Requirements Review

Use for PRDs, requirement documents, user stories, problem statements, and
acceptance criteria.

Check:

- goal, actor, scope, exclusions, main flow, and ownership are explicit
- acceptance criteria are observable, unambiguous, and independently verifiable
- failure, boundary, permission, data, and lifecycle behavior is authorized
- dependencies and non-functional constraints are testable rather than slogans
- terminology and traceability remain consistent with repository evidence

Do not turn a review into architecture or implementation planning. A missing
business decision is an insufficient-basis finding and requires clarification.
